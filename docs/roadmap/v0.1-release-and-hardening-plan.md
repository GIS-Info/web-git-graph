## 1. Executive Summary · 摘要

**EN** — The v0.1.0 feature scope is essentially implemented and the four-module
split (`@web-git-graph/protocol` / `web` / `node` / `vscode` + private demo) is
complete, with a locally green baseline (typecheck, unit, integration,
boundary checks all pass as of 2026-08-02). What blocks the release is not the
code: the GitHub repository (`GIS-Info/web-git-graph`) was only connected on
2026-08-02 and `main` has never been pushed, **nothing is published to npm**,
and both `publish.yml` and `pages.yml` still reference the pre-split
`web-git-graph` single package that no longer exists. Test depth also falls
short of what the original plan required (generative DAG tests, visual
snapshots, stash/rename/binary fixtures). This plan sequences the remaining
work into five milestones: **M0 pipeline repair → M1 first publish (v0.1.0) →
M2 test hardening (v0.1.1) → M3 UX completion (v0.1.2) → M4 VS Code packaging
(v0.2.0)**.

**中文** — v0.1.0 的功能范围已基本实现，四模块拆分
（`@web-git-graph/protocol` / `web` / `node` / `vscode` + 私有 demo）已完成，
本地基线全绿（截至 2026-08-02，typecheck、unit、integration、模块边界检查全部
通过）。当前阻碍发布的不是代码：GitHub 仓库（`GIS-Info/web-git-graph`）
2026-08-02 刚刚关联、`main` 从未推送，**npm 上未发布任何包**，且
`publish.yml` 与 `pages.yml` 仍引用拆分前已不存在的 `web-git-graph` 单包。测试深度也未达到原计划要求（生成式 DAG 测试、视觉快照、
stash/rename/binary fixtures）。本计划将剩余工作排入五个里程碑：
**M0 发布链路修复 → M1 首次发布（v0.1.0）→ M2 测试强化（v0.1.1）→
M3 交互补全（v0.1.2）→ M4 VS Code 打包（v0.2.0）**。

### 2.2 Deviations from the original plan · 与原计划的偏差

**EN** — These are deliberate, documented decisions, not defects; they are
listed so the release checklist reflects reality:

1. **Package architecture** — the plan's single unscoped `web-git-graph`
   package with subpath exports was superseded by four scoped packages under
   `@web-git-graph/*` (decision recorded in the four-module split plan). The
   npm scope/organization `web-git-graph` must now be registered before
   publishing, and the old plan's "unscoped name available" check is obsolete.
2. **VS Code module** — built ahead of schedule; it was not part of the
   original v0.1.0 scope. Marketplace/VSIX delivery is still open (M4).
3. **Cursor signing** — cursors carry a random 128-bit snapshot ID instead of
   a cryptographic signature. Unguessable IDs give equivalent practical
   protection; this plan records it as an accepted decision (see §6).

**中文** — 以下为有记录的主动决策，而非缺陷；列出是为了让发布清单与现实一致：

1. **包架构** — 原计划的无 scope 单包 `web-git-graph`（subpath exports）已被
   `@web-git-graph/*` 四个 scoped 包取代（决策见四模块拆分计划）。发布前必须先
   注册 npm 组织 `web-git-graph`，原计划的"无 scope 包名可用性"检查已作废。
2. **VS Code 模块** — 提前实现，不在原 v0.1.0 范围内。Marketplace/VSIX 交付
   仍未完成（见 M4）。
3. **Cursor 签名** — cursor 携带随机 128 位快照 ID 而非加密签名。不可猜测的
   ID 在实际上提供等价保护；本计划将其记录为已接受的决策（见 §6）。

### 3.2 P1 — Quality gaps · 质量差距

**EN**

- **Layout tests** (5 cases) cover linear/merge/octopus/pagination/dangling,
  but the plan's *generative DAG tests* (random DAGs verified for connection
  integrity, determinism, and colour reuse) and multi-root fixtures are
  missing.
- **Node integration tests** (4 cases) cover pagination, working tree,
  details, compare, diff, root-commit empty-tree, allowedRoots, and revision
  rejection — but not **stash**, **rename/copy**, **binary diff**, **bare
  repositories**, **timeout/output-limit/concurrency behaviour**, or **path
  traversal attempts**.
- **Contract tests** — the Web→HTTP→Node chain has one happy-path test with a
  mock backend; the plan requires shared protocol fixtures across both real
  adapter chains (HTTP and VS Code RPC) to prevent transport drift.
- **Visual snapshots and accessibility checks** — absent from e2e; the plan
  lists both as CI gates.
- **VS Code tests** — a single RPC codec test; no Extension Host handler test
  against a temp repository, no `@vscode/test-electron` integration test, no
  VSIX install verification.

**中文**

- **布局测试**（5 例）覆盖线性/合并/octopus/分页/悬挂，但缺少原计划的
  **生成式 DAG 测试**（随机 DAG 验证连接完整性、确定性与颜色复用）及多 root
  fixtures。
- **Node 集成测试**（4 例）覆盖分页、工作区、详情、比较、diff、根提交空树、
  allowedRoots、revision 拒绝，但缺 **stash**、**rename/copy**、**二进制
  diff**、**bare 仓库**、**超时/输出限制/并发行为**、**路径穿越尝试**。
- **契约测试** — Web→HTTP→Node 链路只有一个使用 mock backend 的正路径测试；
  原计划要求 HTTP 与 VS Code RPC 两条真实链路共享同一套协议 fixtures，防止
  传输语义漂移。
- **视觉快照与可访问性检查** — e2e 中缺失；原计划将两者列为 CI 门禁。
- **VS Code 测试** — 仅一个 RPC 编解码测试；缺少针对临时仓库的 Extension Host

## 6. Risks and Decisions · 风险与决策

| Risk / Decision · 风险/决策 | Handling · 处理 |
| --- | --- |
| **npm scope squatting / npm 组织被抢注** — `web-git-graph` org is unregistered while the repo becomes public. | Register the org in M0 before pushing the repository. / 在 M0 推送仓库前先注册组织。 |
| **`workspace:*` leakage / `workspace:*` 泄漏** — publishing with `npm publish` would ship unresolvable deps. | Publish only via `pnpm publish`; M1 verifies installability from a clean project. / 仅用 `pnpm publish` 发布；M1 用干净项目验证可安装性。 |
| **Unsigned cursors / cursor 未签名** — plan originally called for signed snapshot IDs. | Accepted: 128-bit random IDs are unguessable and single-purpose; revisit only if snapshot stores become shared across trust boundaries. / 接受现状：128 位随机 ID 不可猜测且用途单一；仅当快照 store 跨信任边界共享时再评估。 |
| **Old `v0.1.0` tag confusion / 旧 tag 混淆** | Delete locally before first push; the release tag is re-cut in M1 on the four-module commit. / 首次推送前本地删除；M1 在四模块提交上重新打 tag。 |
| **Test hardening delays release / 测试强化拖慢发布** | Ship v0.1.0 on the current green baseline; M2 depth lands as v0.1.1. The published surface is additive-only in 0.x per the split plan's versioning policy. / 以当前绿色基线发布 v0.1.0，M2 深度作为 v0.1.1 跟进；0.x 阶段发布面仅做加法。 |
| **Demo GitHub rate limits / demo 受 GitHub 限流** | Documented in demo UI; optional token lands in M3. / 在 demo UI 说明；可选 token 于 M3 落地。 |
